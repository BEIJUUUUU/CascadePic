# 技术方案

## 1. 技术栈

- 语言：Python 3.12
- GUI：PySide6（Qt 6）
- 图片：Pillow，必要时按格式增加可选插件
- 视频播放：VLC / python-vlc
- 视频探测和封面：FFmpeg / ffprobe
- 测试：pytest
- 打包：PyInstaller 目录模式优先，后期评估 Nuitka
- 版本管理：Git + GitHub

当前开发机检测到 Python 3.14、3.10 和 3.9，尚未检测到目标 Python 3.12。正式建立运行环境前需要安装 Python 3.12。

## 2. 架构分层

### UI 层

负责主窗口、瀑布流、图片查看器、视频查看器、设置和快捷键。UI 层不直接执行耗时媒体解码。

### 模型层

保存媒体项目、文件夹状态、排序筛选状态和应用设置等纯数据。

### 服务层

提供目录扫描、媒体探测、图片解码、缩略图生成、缓存和文件操作能力。

### 工作线程层

通过 Qt 线程池执行扫描、缩略图和视频封面任务，并通过信号将结果返回 UI。

## 4. 瀑布流方案

瀑布流是最高风险模块，必须先进行独立原型验证。

原则：

- 模型保存全部轻量元数据，不保存全部完整图像。
- 使用图片原始宽高比预先计算卡片高度和列位置。
- 只绘制或实例化可见区域及其缓冲区项目。
- 滚动方向上的临近项目拥有更高加载优先级。
- 调整窗口宽度或缩略图尺寸时重新计算布局。
- 重新布局尽量以当前锚点项目维持视觉位置。

优先评估基于 `QAbstractItemView`/模型委托的轻量方案；如果 Qt 默认视图无法满足不等高虚拟布局，再实现专用瀑布流视图和布局索引。

## 5. 缩略图管线

1. 扫描得到路径、类型、大小和修改时间。
2. 查询内存缓存。
3. 未命中时查询磁盘缓存。
4. 仍未命中则进入有界线程池生成。
5. 将结果写入磁盘和有限容量内存缓存。
6. 通过 Qt 信号更新对应可见项目。

缓存键至少包括：规范化路径、文件大小、最后修改时间和缩略图规格。

## 6. 并发策略

- UI 主线程：仅处理事件、绘制和轻量状态变更。
- 目录扫描：低并发，分批返回结果。
- 图片缩略图：固定大小线程池，优先可见项目。
- 视频封面：独立低并发队列，避免同时启动大量 FFmpeg 进程。
- 任务需要支持过期判断；切换文件夹后旧任务结果不得污染新视图。

初始并发值通过性能测试确定，不写死为越多越好。

## 7. 图片查看器

- 默认按显示尺寸解码预览，避免超大图片完整展开。
- 支持适应窗口、原始尺寸、缩放和拖动。
- 缩放以指针所在图像位置为锚点。
- 相邻媒体只进行有限预加载。
- 切换和关闭时释放不再需要的解码资源。

## 8. 视频方案

VLC 负责实际播放，FFmpeg/ffprobe 负责批量封面和元信息提取。瀑布流中不自动解码或播放所有视频。

发布时需要明确 libVLC 和 FFmpeg 的分发方式、许可证告知及组件版本。

## 9. 配置和日志

MVP 使用版本化 JSON 配置保存界面偏好、最近目录和缓存限制。日志使用标准 `logging`，默认滚动保存，不记录媒体内容。

如果后续加入标签、评分和大型媒体库，再引入 SQLite。

## 10. 打包策略

第一版优先使用 PyInstaller 目录模式：

- 更容易携带 Qt、VLC 和 FFmpeg 组件
- 更容易诊断缺失依赖
- 通常比单文件自解压模式启动更直接

稳定后再评估安装包、单文件模式或 Nuitka。
